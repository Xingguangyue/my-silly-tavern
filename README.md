# 我的酒馆 · My Tavern

一个角色扮演对话前端。核心目标只有一句话：

> **能自己讲清「这一次到底把什么内容、按什么顺序发给了模型」。**

所以它不追求功能多，而是把「请求是怎么拼出来的」这件事做成了看得见、查得到、改得了的。

---

## 快速开始

### 方式一：直接双击 `index.html`（推荐）

不需要装任何东西，不需要服务器。默认就是**模拟回复**模式，所以**不填 API Key 也能完整体验**
——世界书匹配、消息三态、面板渲染、发送前预览、已发送快照全都能看。

### 方式二：本地服务器

只有在浏览器把跨域请求拦掉、直连模型失败时才需要：

```
E:\Python312\python.exe serve.py
```

然后打开 `http://localhost:8000`，并在右边「设置」里勾上**「走本地代理 serve.py」**。

它做两件事：提供静态文件 + 把 `POST /api/chat` 转发给模型服务（转发这一步由 Python 发出，
不受浏览器 CORS 限制）。只监听 `127.0.0.1`，不对外开放。

---

## 怎么接上真实的模型

右侧「设置」页填三项，然后点「保存设置」：

| 项 | 说明 |
|---|---|
| API 地址 | OpenAI 兼容地址，例如 `https://example.com/v1` |
| API Key | 你自己的 Key |
| 模型名 | 例如 `gemini-3.8-flash` |

然后**取消勾选「模拟回复」**才会真正联网。

> ⚠️ **Key 会以明文保存在浏览器里。** 它跟着聊天数据一起写进 `localStorage`
> （设置页那个输入框只是 `type="password"`，挡的是肩膀，不挡存储）。
> 所以：**不要在别人的电脑、或公共电脑上填真实 Key**；演示用模拟回复模式就够。

## 功能

### 等级 1 · 会话与消息

- 会话的新建 / 切换 / 重命名 / 删除
- 消息发送、流式输出、重新生成、中止
- 会话导入 / 导出（导入时明确区分**覆盖**与**创建副本**）
- 数据持久化（刷新不丢）

### 等级 2 · 消息三态 + 世界书

三种状态**互相独立**，这是本项目的重点之一：

| 状态 | 界面上 | 会发给模型吗 |
|---|---|---|
| **隐藏** | 默认看不见（可勾「显示已隐藏」展开） | **会**——隐藏只是显示上的事 |
| **不发送** | 看得见，但有明确标记 | **不会** |
| **删除** | 消息消失 | 不可逆，不要拿删除当隐藏用 |

世界书的匹配规则：

1. 扫描范围 = 最近 N 条消息 + 本次待发送的那条用户消息（N 可在世界书页调）
2. 单条消息正文内做**子串包含**匹配，**不跨消息拼接**
3. 已启用的「常驻」条目直接入选；**禁用的一律排除**
4. **不递归**扫描世界书正文，也不扫描角色设定和提示词模块
5. 优先级从高到低排序；同优先级按 ASCII ID 升序；同一条目最多插入一次

### 等级 3 · 角色卡 / 预设 / 面板

- **提示词预设**：启用的模块按「顺序」拼在请求最前面。导入的 JSON 只要符合本应用的格式，
  **不改一行业务代码**就能直接用。
- **角色卡（Character Card V2 子集）**：见下面的「兼容范围」。
- **`<tavern-panel>` 渲染**：模型输出下面两种标签会被渲染成小界面，而不是显示成一堆 JSON。

```
<tavern-panel type="status">{"hp":18,"hpMax":20,"令咒":3}</tavern-panel>
<tavern-panel type="choices">{"options":[{"label":"按钮文字","text":"点了之后填进输入框的内容"}]}</tavern-panel>
```

状态条是**通用**的：任何成对的 `X` + `XMax` 都会画成一根进度条，不写死字段名。

解析失败时（JSON 不合法 / 标签没闭合 / 不支持的 `type`）会**保留原文并指出具体问题**，
不会把那段内容悄悄丢掉。

### 发送前预览 + 已发送快照

这是两个**不同**的东西，别混：

- **① 发送前预览**：按**当前状态现算**。你一改消息、世界书或扫描深度，它立刻跟着变。
  它回答「**如果现在发，会发什么**」。
- **② 已发送快照**：**发出去那一刻**的记录，**只读**。之后再改历史消息它也不会变。
  它回答「**上次实际发的是什么**」。

检查视图能回答：实际发送了哪些内容、顺序是什么 / 每部分来自哪条消息、哪个模块或哪个世界书条目 /
哪个关键词触发了世界书 / 某条内容**为什么没有发送**（不发送、未完成、内容为空、
世界书条目已被禁用、世界书关键词未命中）。

### 等级 4 · 变量与动态模板

**未实现。** 本项目只做到等级 3。

## 兼容范围（如实说明，不做超范围的承诺）

**角色卡只实现一个明确子集：名称 / 描述 / 开场白 / 内嵌世界书。**

- 不认识的字段、以及未知的 `extensions`，**全部原样保留**，导出时写回去
- 导出的仍是 Character Card V2 结构，不破坏原有的其它字段
- 角色卡页会列出**字段映射表**和**被忽略的运行规则**，一眼能看出哪些没生效

**`<tavern-panel>` 只支持 `type="status"` 和 `type="choices"`**，其它 `type` 按「不支持」处理
（保留原文 + 提示），不会静默忽略。

**API 走 OpenAI 兼容格式**（`/chat/completions`），流式解析标准 SSE（`data: {...}` + `data: [DONE]`）。

## 文件结构

```
SillyTavern/
├── index.html      界面骨架（三栏：会话 / 对话 / 预览与配置）
├── style.css       样式
├── tavern.js       全部逻辑 —— 本项目唯一需要维护的代码文件
├── serve.py        可选的本地开发服务器（静态文件 + 代理转发）
└── sample/         可以直接导入的示例
    ├── card-saber.json      角色卡示例
    └── preset-suspense.json 提示词预设示例
```

代码按功能分成 1–14 段并编号（存储 / 建会话 / 消息三态 / 上下文 / 世界书匹配 / 拼请求 /
调模型 / 流式与生成 / 渲染 / 面板解析 / 导入导出 / 事件绑定 / 预设 / 角色卡）。

在 `tavern.js` 里搜 `====`（段分隔注释）或搜段落编号就能跳到各段。
第 1–7 段用 `// 1.===` 风格，第 8–14 段用 `/* === … */` 风格。

## 数据存在哪

浏览器的 `localStorage`，键名 `tavern.db.v1`（会话、消息、世界书、预设、角色卡、已发送快照都在里面）。

因为这是**浏览器级**存储，不是文件级的：

- 换个浏览器、换台电脑 → 数据就没了
- 用无痕窗口 → 关掉就没了
- 浏览器禁止站点数据 → 页面会**照常能跑**，只是刷新后回到初始状态

## 交付 / 发布

需要把一个文件发给别人时，可以把三份源码内联成一个「单文件版」HTML，
拷过去双击就能跑（同样不需要 Python、不需要服务器、不需要 Key）。
打包脚本在项目外，生成的产物**不提交进本仓库**——它是产物，性质等同于 `node_modules`。

## 已知限制

- 上下文用量是**估算**的：汉字按 1 字 ≈ 1 token、其余按 4 字符 ≈ 1 token 粗算，每条消息再 +4。
  它用来判断「上下文是不是快满了」，不是精确计数
- 模型**不一定**听话地按预设格式输出；面板渲染对输出格式做了容错，但不能保证模型一定输出标签
- 没有服务端，所以没有账号、没有多端同步
